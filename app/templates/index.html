What is Bug Finder?

Bug Finder searches old GitHub issues for problems that look similar to the one you are currently dealing with.

Describe the problem in your own words, and Bug Finder will show issues that may be related.

How to use it

  1. Choose how you want to search. Search Indexed Repositories searches repositories already loaded into Bug Finder. Two examples are pandas-dev/pandas and open-metadata/OpenMetadata.
  2. Or use Search Public GitHub to search current public GitHub issues.
  3. If you know which repository the bug is from, enter it in the optional Repository box. For example: psf/requests.
  4. Describe your bug in your own words. Include useful details like the error, feature, or behavior that is not working.
  5. Press Search.
  6. After you search, scroll down to see the closest matching issues.
  7. Open any result to read the full GitHub issue and see if it contains a fix, workaround, or similar problem.

Search Indexed Repositories

Search repositories that have already been added to Bug Finder.

Search Public GitHub

Search current public GitHub issues.

Leave this blank to search all public GitHub issues. Enter a repository if you know where the bug is happening.

Live GitHub search may take a little while to finish. Please wait for the results before clicking Search again. Repeated searches can temporarily hit GitHub's API rate limit.

Add issues to Bug Finder

There are two ways to add GitHub issues so they stay available in the indexed search.

  1. Add a GitHub Repository if you want Bug Finder to download the repository's bug issues for you.
  2. Upload GitHub Issue Data if you already have GitHub issues saved as a JSON file.

Most users can just use Add a GitHub Repository. The JSON option is only useful if you already have GitHub issue data saved in a file.

Add a GitHub Repository

Enter a public repository such as psf/requests.

Bug Finder will download its issues labeled "bug", store them, and make them searchable.

Large repositories can take several minutes to process.

Already Have GitHub Issue Data?

Most users do not need this. Use this only if you already have GitHub issues saved as a JSON file.

The file must contain GitHub issue-style JSON. The records should look like issue data returned by GitHub and include fields such as an issue ID, issue number, title, state, dates, labels, and other issue information.

Not sure what GitHub issue JSON looks like? GitHub's official Issues API documentation includes example responses showing the structure of GitHub issue records.
